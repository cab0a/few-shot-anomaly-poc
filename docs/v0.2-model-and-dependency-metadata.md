# v0.2 Model and Dependency Metadata Verification

## 日本語概要

## English Summary

This record verifies official distribution metadata for the preregistered DINOv2 source snapshot, ViT-S/14 checkpoint, PyTorch CPU wheel, and direct Python packages without acquiring their binary artifacts. The available metadata supports proceeding to an isolated dependency lock and a v0.2-specific license inventory. It does not yet authorize installation, checkpoint acceptance, CPU benchmarking, or anomaly evaluation.

## Verification Method

The verification used:

- HTTPS `HEAD` requests with redirects enabled for the source archive, checkpoint, and selected PyTorch wheel;
- the official PyTorch CPU simple-index page and its PEP 658 core-metadata link;
- an in-memory download of the 37,906-byte PyTorch `METADATA` text, not the wheel;
- PyPI JSON metadata for NumPy, pytest, and Ruff;
- Git tag and revision resolution for PyTorch, CPython, and uv; and
- fixed-revision upstream license and model-source pages.

No source archive, model checkpoint, wheel, source distribution, package installation, or dataset object was downloaded. Small text metadata, license pages, and source pages are not treated as executable assets.

HTTP metadata is evidence about the object served on the verification date. It is not a substitute for hashing the later acquired bytes.

## License Boundary Decision

No metadata-level license blocker was identified for the planned noncommercial public portfolio experiment.

The boundaries remain:

- original v0.2 repository code and documentation: PolyForm Noncommercial License 1.0.0;
- standard DINOv2 source and checkpoint: Apache License 2.0;
- PyTorch CPU wheel: the exact composite license expression and bundled notices distributed with that wheel;
- NumPy, pytest, Ruff, and transitive packages: their respective distribution terms;
- VisA: CC BY 4.0; and
- no PolyForm restriction applied to any third-party material.

This is not final license approval for installation or redistribution. Binary wheels can contain separately noticed native components that are not fully represented by one top-level expression.

The v0.1 `NOTICE.md` and dependency inventory are freeze-listed historical files. A new `docs/v0.2-dependencies-and-licenses.md` must inventory the locked v0.2 distributions and extracted license files before installation or executable DINOv2 use. The README may link that new record without modifying the v0.1 freeze.

## Required Metadata Record Format

Every later acquired source archive, wheel, metadata file, and checkpoint must have one record containing:

- schema version and record type;
- stable asset ID and role;
- verification and acquisition dates;
- requested and resolved URLs;
- HTTP status, content type, content length, ETag, Last-Modified, and range support when supplied;
- official filename and distribution version;
- upstream-published digest algorithm and value, or explicit `none`;
- independently observed byte count and SHA-256;
- checksum status: `upstream_verified` or `observed_only`;
- source revision or release tag where applicable;
- license identifier or exact license expression;
- extracted license and notice filenames with their SHA-256 values;
- safe-load or archive-structure checks;
- whether the artifact was installed;
- confirmation that the artifact is outside Git; and
- the controlling preregistration and acquisition commit identities.

Null or absent upstream metadata must remain explicit. An ETag must never be copied into a checksum field.

## Stop Conditions for the Next Milestone

Stop and do not acquire or install executable artifacts if:

- the resolver cannot use exactly CPython 3.13.14, NumPy 2.5.1, and PyTorch 2.13.0+cpu;
- the resolver selects a CUDA, ROCm, XPU, nightly, prerelease, source-build, or wrong-platform PyTorch artifact;
- any selected filename, URL, or published SHA-256 differs from the verified direct-distribution metadata without a new preregistration;
- a selected distribution is yanked;
- a transitive distribution lacks reviewable source, hash, or license metadata;
- the lock requires an unregistered direct dependency;
- the v0.2-specific license inventory cannot separate third-party terms from PolyForm;
- the checkpoint HEAD byte count or fixed source revision changes before acquisition; or
- the acquisition workflow would write an artifact into Git.

## Decision

The official metadata is sufficient to proceed to:

1. a separate `environments/v0.2-preflight/` dependency declaration;
2. a metadata-only locked resolution;
3. review of every selected transitive distribution;
4. a preliminary v0.2-specific dependency and license inventory; and
5. a committed lock and metadata-review checkpoint.

Only after those steps pass may controlled binary acquisition for checksum and license-file inspection begin. Installation and executable use remain forbidden until the acquired artifacts pass their digest and content checks and the v0.2-specific license inventory is completed and committed.

No DINOv2 method, model asset, package, CPU result, or VisA performance result is adopted or present at this stage.
