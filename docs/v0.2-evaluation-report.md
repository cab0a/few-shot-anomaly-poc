## English Summary

This report completes the preregistered v0.2 comparison of two classical baselines and one DINOv2 patch-nearest-neighbor method on the VisA `pcb2` category. All three methods are `REJECT`, and the project decision is `REJECT`. The decision follows the first failed ordered hard gate for each method; no weighted score, waiver, threshold revision, rescoring, or image-content review was used.

## Status

**v0.2 project decision: `REJECT`.**

ECC residual and Patch HOG + One-Class SVM passed the fit, leakage, and fixed-threshold normal-FPR gates, then failed the anomaly-recall gate. DINOv2 passed the fit and leakage gates, then failed the earlier normal-FPR gate. Later gates were not evaluated after each first failure.

This is a completed negative PoC result. It does not support deployment, production readiness, or generalization beyond the fixed public case study.

## Question Evaluated

The hypothetical question was whether any fixed normal-only anomaly method justified a next controlled validation when:

- exactly 20 normal reference images were available;
- anomaly labels could not be used for training or threshold calibration;
- the operating threshold came from a separate normal-only partition;
- final-test scoring ran on CPU;
- labels entered only after immutable label-free scores were committed and reproduced; and
- adoption required every hard gate to pass.

The stakeholder, operating requirements, and acceptance limits are hypothetical. They are not customer requirements or recommendations for an actual inspection process.

## Fixed Methods

| Method | Role | Fixed image-score idea |
| --- | --- | --- |
| ECC residual | classical baseline | align to a normal template and aggregate residual intensity |
| Patch HOG + One-Class SVM | classical comparator | model fixed-position normal HOG patches and aggregate anomalous patch scores |
| DINOv2 ViT-S/14 at 224 | new representation candidate | compare test patch tokens with a 5,120-patch normal memory bank using exact cosine distance |

DINOv2 used the pinned standard `dinov2_vits14` checkpoint, CPU `float32`, 256 patch tokens per image, exact blocked distance calculation, and the mean of the two largest per-image patch distances. No method was retuned after entering the `pcb2` boundary.

## Data and Partitions

Only the official VisA `pcb2` one-class split was used.

| Partition | Use | Count | Class access |
| --- | --- | ---: | --- |
| Normal reference | fit each fixed method | 20 | known normal only |
| Normal calibration | set one threshold per method | 881 | known normal only |
| Final test | one label-free score run, then evaluation | 200: 100 normal and 100 anomaly | hidden during scoring; revealed once afterward |

Seed `42` and the frozen SHA-256 path-ranking rule selected the references. Reference, calibration, and final-test records were checked for overlap and duplicate paths. Final-test scorers received opaque asset IDs, not semantic paths, split data, classes, the sealed mapping, or the ordering key.

Raw VisA files, masks, extracted arrays, fitted states, source archives, model weights, and the sealed pre-reveal mapping are not committed.

The nearest-rank 95th-percentile rule and strict `score > threshold` classification rule remained unchanged during final-test scoring and evaluation.

## Ordered Hard-Gate Outcomes

The frozen order was method fit, test leakage, final-test normal FPR, final-test anomaly recall, CPU p95 latency, reference budget, anomaly-label use, and reproducibility. Evaluation stopped after the first failed gate for each method.

| Gate | ECC residual | Patch HOG + One-Class SVM | DINOv2 224 NN |
| --- | --- | --- | --- |
| 1. Method fit: `fit_ok` | pass | pass | pass |
| 2. Test leakage: none | pass | pass | pass |
| 3. Normal FPR: `<= 0.05` | pass: `0.04` | pass: `0.05` | **fail: `0.07`** |
| 4. Anomaly recall: `>= 0.90` | **fail: `0.13`** | **fail: `0.16`** | not evaluated |
| 5. CPU p95: `<= 1.0 s/image` | not evaluated | not evaluated | not evaluated |
| 6. References: exactly 20 | not evaluated | not evaluated | not evaluated |
| 7. Anomaly training labels: none | not evaluated | not evaluated | not evaluated |
| 8. First-10 offline reproduction: pass | not evaluated | not evaluated | not evaluated |

The later process and latency evidence exists and is reported, but the ordered decision procedure does not mark a later gate as passed after an earlier failure. AUROC, AUPRC, lower latency, another method's outcome, or a visual impression cannot waive a failed gate.

## Failure-Case Evidence

After label reveal, deterministic code selected up to five errors per type and method:

- false positives by anomaly score descending, then opaque asset ID ascending; and
- false negatives by anomaly score ascending, then opaque asset ID ascending.

ECC produced four false positives, so its public file contains four false-positive and five false-negative selections. Patch HOG and DINOv2 each contain five selections of both types. The records preserve asset ID, revealed source path, class, prediction, score, threshold, margin, status, failure code, and rank.

No selected image was opened or displayed. The frozen schema requires a failure-review disposition in every method decision; `no_material_boundary` is used as a neutral schema value for these early hard-gate rejections, not as evidence that a visual review found no boundary. No causal claim about alignment, lighting, layout, defect type, or defect size is made.

## Interpretation

DINOv2 produced the strongest ranking values and the highest recall among the fixed methods. That result is useful comparative evidence, but it does not meet the operating requirement. At its unchanged normal-only threshold, it missed 66 of 100 anomalies and exceeded the normal-FPR limit with seven false positives.

The two classical methods stayed within the normal-FPR condition but detected only 13 and 16 of 100 anomalies. Their operating points therefore fail the stated purpose even though every final-test score was produced successfully and the measured p95 latencies were below one second.

The study shows that stronger ranking does not guarantee an acceptable fixed operating point. It does not establish why the score distributions behaved this way, and it does not show that DINOv2 or either classical method is unsuitable for every anomaly-detection setting.

## Decision

| Scope | Decision | First controlling reason |
| --- | --- | --- |
| ECC residual | `REJECT` | anomaly recall `0.13 < 0.90` |
| Patch HOG + One-Class SVM | `REJECT` | anomaly recall `0.16 < 0.90` |
| DINOv2 ViT-S/14 224 NN | `REJECT` | normal FPR `0.07 > 0.05` |
| Project | `REJECT` | every fixed method is rejected; no method is selected |

No weighted aggregate score or hard-gate waiver was used. `ADOPT WITH CONDITIONS` was unavailable because it cannot rescue a failed numerical or process gate.

## Recommended Next Validation

The completed final-test boundary must not be rescored or used for tuning. The next bounded study should be separately preregistered as a development-only `pcb2` diagnostic:

1. review only the mechanically selected v0.2.7 cases and separate visible observations from inferred causes;
2. examine normal-score transfer using a new development-only partition;
3. define one fixed, observable method change only if the diagnostic evidence supports it; and
4. evaluate that change on a new untouched boundary rather than the completed 200-image final test.

This proposal is not authorization to rerun v0.2 or a promise that another method will pass.

## Known Limitations

- One VisA category, one official split, one seed, and one 20-image reference set were evaluated.
- The benchmark does not represent a specified camera, process, defect taxonomy, prevalence, review cost, or business loss.
- No confidence interval, reference-set sweep, significance test, or cross-category estimate is provided.
- Selected image content was not reviewed, so no visual failure taxonomy or causal explanation is claimed.
- Image-level metrics do not measure localization or segmentation quality.
- DINOv2 was evaluated only at 224 resolution with one frozen representation and aggregation rule.
- CPU latency is specific to the recorded machine, environment, and measurement boundaries.
- The DINOv2 boundary excludes inter-process transfer and is not end-to-end application latency.
- Published class labels and paths entered only after the score-side bundle was fixed; this completed test cannot be treated as untouched again.
- Results must not be generalized to other VisA categories or real inspection data.
