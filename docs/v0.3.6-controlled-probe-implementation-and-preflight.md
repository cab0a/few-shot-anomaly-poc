## English Summary

The fixed normal-only probe is implemented and verified using generated
pixels and fake scorers. The synthetic pipeline covers 60 base images,
five conditions, three method slots, 900 records, and 15 paired summaries.
The existing method implementations, fitted states, thresholds, input
partition, observations, and join remain unchanged. The real controlled
experiment has not run. This milestone implements and validates the runner;
it does not produce real diagnostic scores or a diagnostic decision.

## Fixed Contract and Execution Boundaries

The implementation follows the existing
[preregistration](v0.3-development-diagnostic-preregistration.md),
[configuration](../configs/v0.3.yaml), and
[artifact schema](../schemas/v0.3/diagnostic-artifacts.json).
No frozen contract file is edited. The clean execution source must be
pushed to `origin/main` and descend from completed join evidence
`c07eee51c8d5993cceaeeb92b071005c636e4661`.

The 60 images are reconstructed from the hash-locked 881-record normal
calibration manifest and compared byte-for-byte with the committed
[normal partition](../artifacts/v0.3/diagnostics/pcb2-development/normal-diagnostic-partition.csv).
The 20 reference records are excluded. No final-test images, final-test
score values, or new observations are inputs to scoring. Parent artifacts
are read only as bytes for hash verification; their score contents are not
parsed by the probe. The normal partition remains development data.

`--check-only` verifies metadata, dependency identities, all three fitted
state hashes, fixed model downloads, and the extracted DINOv2 source tree.
It imports CPU PyTorch in its isolated environment to check its identity,
but creates no model, reads no image bytes, and creates no probe session.
Image availability and content are therefore checked during `--execute`:
all 60 encoded files must match their recorded hashes before any model
loads or any image decodes, followed by another byte check at each decode.

The inherited adapters, scoring functions, state loaders, and supporting
modules must match their Git blobs at the join evidence commit. Config,
schema, locks, parent artifacts, model files, and fitted states are checked
again during execution and before publication. The v0.2 evidence and all
seven existing v0.3 diagnostic metadata files are immutable.

## Conditions, Adapters, and Summaries

Each base image is decoded once as BGR `uint8`, with EXIF orientation
ignored. Every condition starts from the same read-only original array;
conditions are never chained and retain the original extent.

| Condition | Operation |
| --- | --- |
| `control` | Unchanged decoded pixels |
| `brightness_085` | Float64 multiplication by 0.85, `numpy.rint`, clipping, then `uint8` |
| `brightness_115` | Float64 multiplication by 1.15, `numpy.rint`, clipping, then `uint8` |
| `gaussian_blur` | OpenCV 5 × 5 Gaussian, sigma 1.0, `BORDER_REFLECT_101` |
| `translate_4_4` | Four pixels right/down, `INTER_LINEAR`, `BORDER_REFLECT_101` |

After the original-extent transform, classical inputs use
`cv2.cvtColor(..., COLOR_BGR2GRAY)` followed by the unchanged 512-pixel
preprocessor and existing ECC/HOG scoring functions. DINOv2 uses the
existing BGR-to-RGB 512-pixel adapter and unchanged 224-pixel scorer. The
BGR-to-gray conversion is explicit because the common transformed BGR
array is required by the probe contract. It is not a claim that JPEG's
direct grayscale decoder used in v0.2 yields identical control pixels.
No final-test score comparison is made.

The existing fitted states and thresholds are reused: ECC
`0.6219927985456926`, HOG `0.14960269900890077`, and DINOv2
`0.22208529710769653`. Classification uses strict `score > threshold`.
Successful rows are ordered by method, selection rank, then condition.
There is one invocation per slot, with no timing loop or warmup scoring.

For each non-control condition, all 60 scores are paired with that
method's control scores. Summaries include signed and absolute medians,
nearest-rank p95 absolute delta (the 57th sorted value), threshold counts
and rates, and both crossing directions. Control rows have null delta
statistics and zero crossings. The public schema represents these as
15 rows, including three controls. There are no held-out performance
metrics, AUROC/AUPRC, recall, precision, or latency measurements.

## Isolation and Interrupted Attempts

The root environment performs 600 classical calls. A separate CPU-only
DINOv2 worker consumes 300 staged RGB arrays from an ignored NumPy store
(approximately 236 MB). The manifest binds rank, condition, original
image hash, and RGB hash; it contains no semantic source-image path.
The worker verifies the complete store and each array, loads only the
existing fixed model and memory bank, and returns 300 records. It does
not fit or update the bank. Network attempts during scoring are blocked.

The session is fixed at `work/v0.3.6/controlled-probe/`. Input and scoring
attempts and returned score records are flushed to disk as they occur.
Existing sessions or outputs cause a stop, including in `--check-only`.
There is no force, overwrite, resume, or automatic retry mode.

An exception, malformed record, changed hash, failed scorer result, or
interruption preserves the available audit and marks the run incomplete.
A valid failed-score result retains its original failure code and sentinel
before stopping. This runner does not drop failed pairs or invent missing
delta values. Complete paired summaries require 900 successful records;
an incomplete collection remains evidence for the later preregistered
incomplete-evidence decision, not a successful probe.

Only a complete validated run writes `controlled-scores.csv` and
`condition-summaries.csv` under the existing diagnostic artifact directory.
Both writes are exclusive; `complete.json` is written last in the private
session. A storage error may leave a partial public file or pair: these
are preserved, rejected as incomplete, and must not be deleted to rerun.
CI accepts the existing seven files or a semantically valid complete pair
in addition, while retaining every original hash assertion. The final
diagnostic decision and complete diagnostic manifest are a later stage.

## Verification Evidence and Limits

The committed [synthetic verification record](../artifacts/v0.3/synthetic/controlled-probe-verification.json)
binds the pipeline implementation and fake output identities. It records
60 generated images, 900 fake score rows, and 15 summaries, with explicit
false flags for VisA access, real method execution, model/state loading,
latency measurement, and real probe execution. Tests reconstruct the
synthetic output hashes and check the recorded implementation hashes.

The tests cover immutable pixels, independent condition inputs, rounding
and clipping, Gaussian edge behavior, translation borders, strict
threshold ties, both crossing directions, nearest-rank p95, serialization,
exact ordering/counts, changed source bytes, malformed scores, changed
images, interrupted attempts, transport corruption, and no overwrites.
Separate isolated PyTorch tests exercise the existing DINOv2 math using
synthetic tensors and test models. No real checkpoint forward pass or
VisA-derived anomaly score is part of this verification; runtime or data-dependent
scoring failures can still occur during the first real execution.

Local repository validation passed: **753 tests passed**, with two
PyTorch test modules skipped in the root environment. Those modules were
run separately in the pinned isolated environment: **10 tests passed**.
Ruff passed; the Markdown check had no content failures. The metadata-only
preflight passed from clean, pushed implementation source
`af05bc7992df2f87a84cde863cf2490fd055af47`:

```text
Preflight passed: source_commit=af05bc7992df2f87a84cde863cf2490fd055af47
60 normal identities, fixed states and both runtimes verified.
No image bytes read, model loaded, score computed, or probe session created.
```

The actual probe remains unrun. There are no real controlled-score or
condition-summary outputs and no real probe session. The DINOv2 runtime
and pinned model files were restored and verified successfully; the
preflight did not deserialize model weights or fitted state.

## Prepare and Check on the Execution PC

Run from the repository root in WSL Linux x86-64. The external data and
fitted states must already be [restored from Drive](external-data-storage.md).
The runtime preparer restores only the existing locked isolated environment
and the previously recorded official DINOv2 downloads, verifies their exact
hashes and source extraction, and never loads weights or accesses images.
Existing mismatched assets stop rather than being overwritten.

```bash
export PATH="$PWD/work/bootstrap/bin:$PATH"
git pull --ff-only &&
uv sync --locked &&
python3 scripts/prepare_v0_3_6_probe_runtime.py &&
uv run --locked --no-sync python scripts/run_v0_3_6_controlled_probe.py --check-only
```

The ignored local `uv` bootstrap is optional if the pinned `uv 0.11.32`
is already installed on PATH. The preparer is safe to repeat with identical
files. Git stores restoration code and identities; Drive stores external
data and fitted state; environment/model caches are rebuilt at fixed
identities without copying them manually between PCs.

The real execution is deliberately a separate command, **not run in this
milestone**:

```bash
uv run --locked --no-sync python scripts/run_v0_3_6_controlled_probe.py --execute
```

Do not rerun an existing session. Preserve any stopped attempt for review.
The immutable visual observations still fail the per-method visual
prerequisite; controlled results alone cannot change that finding. The
formal diagnostic decision remains pending, and the v0.2 project remains
`REJECT`.
