## English Summary

This milestone provides a command that joins the 28 immutable v0.3.4
observations to the fixed 29 method-case records. It verifies the completed
first pass and parent evidence, writes the existing contracted CSV without
overwriting, and prints descriptive unique-asset counts. The implementation
has been tested with synthetic observation records. The real join has not
yet been executed. No image access, anomaly scoring, or diagnostic decision
is part of this command.

## Run Once

From the repository root in the locked WSL environment:

```bash
export PATH="$PWD/work/bootstrap/bin:$PATH"
git pull --ff-only &&
uv sync --locked &&
uv run --locked --no-sync python scripts/run_v0_3_5_observation_join.py
```

The first line enables the existing local uv installation on PCs where it
is not already on `PATH`. The runner prints its execution commit, writes
`artifacts/v0.3/diagnostics/pcb2-development/observation-case-join.csv`, and
reports:

```text
29 method-case records joined from 28 immutable observations.
```

It also prints the output SHA-256 and per-method unique-asset counts for
the three preregistered visual signal families. These are descriptive
counts only. Keep the terminal output for the execution report and commit
the new CSV after verifying it. Until that evidence is committed, the
worktree will contain the expected new output file.

For an optional preflight before the first join, append `--check-only`.
It verifies the metadata without constructing or writing a join. After
the output exists, both modes stop rather than replacing it. Preserve the
file; do not remove it to make a repeated run succeed. The artifact tests
verify a present join against the exact immutable input records:

```bash
uv run --locked --no-sync pytest -q tests/test_committed_v0_3_inventory.py
```

Do not run `run_v0_3_4_first_observation.py` again for this stage.

## Join and Reporting Rules

The output follows the existing `observation_join` contract in
[`schemas/v0.3/diagnostic-artifacts.json`](../schemas/v0.3/diagnostic-artifacts.json).
The 29 records retain the fixed method, case-type, and rank ordering. Every
observation field is copied verbatim by opaque asset ID. `asset-000112`
therefore appears twice, once for ECC and once for DINOv2, with identical
observation fields. No source paths or numerical scores are added.

Visual counts deduplicate assets within each method and family. Framing
and pose count as one family when either field is `yes`; `uncertain` does
not count as `yes`. An asset associated with two methods can count once
for each method. The command does not label any family as supported or
evaluate a new decision: the fixed controlled-normal evidence is still
required. The completed v0.2 `REJECT` decision remains unchanged.

Changed hashes, incomplete first-pass records, missing or duplicated IDs,
wrong ordering, an invalid completion checkpoint, unpushed or modified
source, unexpected diagnostic files, or an existing output stop execution.
Writing uses exclusive creation. A partial file after a storage failure
is preserved for inspection and must not be treated as a complete result.

## Validation and Next Boundary

Synthetic tests cover exact 28-to-29 joining, the shared asset, verbatim
notes and null values, deterministic serialization, missing/duplicate/out-of-order
records, completion-boundary rejection, changed input identities,
per-method unique counts, source checks, and overwrite refusal. The command
is also tested with an existing v0.3.4 session and a metadata-only checkout.
The tests do not read or decode any VisA images.

The locked root test suite passed with `719 passed, 2 skipped`; Ruff and
Markdown content checks passed. The two skips are the existing
PyTorch-dependent modules, since this metadata-only environment does not
install PyTorch.

After execution, verify and commit the join with its observed output hash
and factual report. A later stage may implement the already preregistered
60-normal, five-condition, three-method controlled probe. This runner does
not execute that experiment or change any observation, transformation,
method parameter, threshold, or diagnostic signal rule.
