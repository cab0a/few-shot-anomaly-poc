# Evaluation Artifact Schema

## Scope

This document defines the v0.1 machine-readable evaluation artifact contract
before final-test scoring. It does not contain a VisA result, threshold,
benchmark, failure observation, or decision.

The controlling machine-readable descriptor is
[`schemas/v0.1/evaluation-artifacts.json`](../schemas/v0.1/evaluation-artifacts.json).
Its contract version is `evaluation-artifacts/v0.1`.

## Artifact Root

Each immutable evaluation bundle uses:

```text
artifacts/v0.1/evaluation/<run-id>/
```

`run-id` must match `^[a-z0-9]+(?:-[a-z0-9]+)*$` and must express a stable
purpose, not a timestamp. The planned synthetic bundle uses
`synthetic-e2e`. The first final-test run will use
`first-fixed-final-test` after the freeze checkpoint is recorded.

Each method has its own directory:

```text
<run-id>/
├── artifact-manifest.json
├── ecc_residual/
└── patch_hog_one_class_svm/
```

An artifact writer must refuse to overwrite an existing bundle.

## Leakage Boundary

`scores.csv` and `classifications.csv` contain no observed class label.
`revealed-labels.csv` is written only after label-free batch classification
has completed and the final-test label reveal boundary has validated the exact
path join. This separation makes accidental label use in scoring artifacts
visible.

The fixed threshold can be regenerated from the `partition=calibration` score
rows. The final metrics can then be regenerated by joining
`classifications.csv` and `revealed-labels.csv` on `run_id`, `method`, and
`relative_path`, then applying the fixed metric implementation. Missing, extra,
duplicate, or reordered paths remain errors.

## Contract Inventory

| Contract | File | Purpose |
| --- | --- | --- |
| Score | `<method>/scores.csv` | Label-free calibration and final-test scores with method diagnostics |
| Classification | `<method>/classifications.csv` | Label-free decisions at the calibration-only threshold |
| Label reveal | `<method>/revealed-labels.csv` | Post-boundary true classes keyed by the same paths |
| Metrics | `<method>/metrics.json` | Image-level ranking and fixed-threshold metrics |
| Latency | `<method>/latency.json` and `<method>/latency-observations.csv` | CPU summary, environment, and every timed invocation |
| Failure | `<method>/failure-cases.csv` | Mechanically selected false positives and false negatives |
| Decision | `<method>/decision.json` | Ordered hard-gate outcomes and the method-level decision |
| Bundle manifest | `artifact-manifest.json` | Provenance and SHA-256 identity of every bundle file |

The schema descriptor fixes every CSV header, primary key, sort key, nullable
field, enum where applicable, and every required JSON key.

## Deterministic Serialization

All files use UTF-8, LF line endings, and one final newline. JSON uses
two-space indentation, lexicographically sorted keys, unescaped Unicode, and
rejects NaN and infinity. CSV uses a header and RFC 4180 comma-separated
records with minimal quoting. Empty CSV cells represent null, booleans use
lowercase `true` and `false`, and finite floats use the CPython 3.13 shortest
round-trip decimal representation.

Rows must follow their declared sort keys. Duplicate primary keys, absolute
paths, timestamps, and non-finite numbers are forbidden. Method diagnostics in
the score table use a canonical compact JSON object so method-specific evidence
does not change the stable common columns.

Score rows are ordered by method, then calibration before final test, then
relative path. Their primary key includes the partition.

## Integrity and Reproduction

`artifact-manifest.json` records:

- contract version and stable run ID
- synthetic or final-test run kind
- dataset and category identifiers
- source Git commit
- SHA-256 of the fixed project configuration
- SHA-256 of the partition manifest
- relative path, artifact type, method, record count, and SHA-256 for every
  artifact file

Manifest file entries are sorted by relative path. The manifest itself is not
listed inside itself because a file cannot contain its own final digest.

Regeneration succeeds only when the produced relative file set, record counts,
and SHA-256 values match the committed bundle manifest under the documented
numeric and environment boundary. A mismatch must remain visible; the existing
bundle must not be silently replaced.

## Data and License Boundary

Artifacts may contain relative paths, numerical records, and bounded textual
analysis. Raw VisA images, masks, archive content, and machine-specific absolute
paths are forbidden.

VisA-derived labels and numerical results remain attributable dataset-derived
material governed separately from the project's PolyForm-licensed original
code and documentation. If a later public figure contains VisA image content,
the separate attribution and modification requirements in the
[evaluation plan](evaluation-plan.md) apply. No image artifact is defined at
this milestone.

## Known Limitations

- The contract preserves one fixed v0.1 evaluation, not a general experiment
  tracking system.
- JSON and CSV structure does not prove that an upstream method was correct;
  primitive validators and reproduction checks provide that evidence.
- CPU latency values are specific to the recorded environment and measurement
  boundary.
- A future schema change requires a new contract version and must not reinterpret
  an existing v0.1 bundle.
