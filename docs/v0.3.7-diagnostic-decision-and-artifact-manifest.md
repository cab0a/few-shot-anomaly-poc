## English Summary

The completed diagnostic decision is **`STOP: NO BOUNDED DIAGNOSTIC SIGNAL`**.
All required evidence is complete, but no family meets both the visual
and numeric criteria for the same method. No family is selected for a
follow-up preregistration. The decision and complete artifact manifest
close the 11-file diagnostic bundle. The v0.2 method and project
`REJECT` decisions remain unchanged.

## Decision and Evidence

The [preregistered signal rule](v0.3-development-diagnostic-preregistration.md)
requires at least three unique visual-yes assets for a method, plus one
matching condition with at least six normal-to-anomalous crossings or a
median absolute score delta at least 10% of that method's fixed threshold.
Both requirements must hold for the same method. The family priority is
framing/pose, exposure, then blur; no weighted score is used.

The closure verified the immutable
[28 observations](../artifacts/v0.3/diagnostics/pcb2-development/blind-observations.csv),
[29 joined cases](../artifacts/v0.3/diagnostics/pcb2-development/observation-case-join.csv),
[900 scores](../artifacts/v0.3/diagnostics/pcb2-development/controlled-scores.csv), and
[15 summaries](../artifacts/v0.3/diagnostics/pcb2-development/condition-summaries.csv).
All 900 scores were successful. The joined observations reproduce from the
original first-pass records, and the summaries reproduce from the saved
scores with the fixed thresholds.

| Family in priority order | Visual yes ECC / HOG / DINOv2 | Numeric requirement met | Supported |
| --- | --- | --- | --- |
| Framing or pose | 0 / 0 / 0 | No method | No |
| Global exposure | 0 / 0 / 0 | ECC brightness ×1.15, 13 crossings | No |
| Blur | 2 / 1 / 1 | No method | No |

ECC's exposure response passes the crossing requirement but cannot pass
the visual requirement. The other method-condition combinations pass
neither numeric alternative. A large descriptive p95, visual counts
pooled across methods, or localized/diffuse-change tags cannot replace
the frozen rule. The [first controlled-probe report](v0.3.6-first-controlled-probe.md)
preserves the full numeric results.

The [decision JSON](../artifacts/v0.3/diagnostics/pcb2-development/diagnostic-decision.json)
records `status: complete`, a null `selected_family`, and each family's
method and condition evaluations. The trace includes unique visual counts,
numeric values and limits, inclusive comparisons, and support results.
It records false flags for weighted scoring, a revised v0.2 decision, and
a performance claim.

This decision closes the registered diagnostic without selecting a
bounded follow-up. It does not establish the absence of exposure, pose,
or blur effects. The visual evidence comes from one AI reviewer without
comparison images or human validation, and `uncertain` never counts as
`yes`. The controlled images were previously used normal development
data; the diagnosis makes no held-out performance or causal claim.

## Verification and Reproduction

The implementation checks decision precedence, same-method conjunction,
unique visual assets, fixed family priority, either brightness condition,
inclusive crossing/delta limits, and the exclusion of descriptive p95
from support. Manifest checks reject missing, duplicate, escaping,
self-referential, changed-hash, and changed-count entries. Existing or
partial outputs are preserved and cannot be overwritten.

The root suite passed **775 tests**, including 22 diagnostic closure
checks, with two PyTorch modules skipped in that environment. This closure
uses saved metadata and requires no PyTorch worker, external images,
Drive restore, or fitted-state loading. Generation and artifact verification
did not load a model, invoke a scorer, decode/display images, or rescore
the final test. Regression tests use existing synthetic fixtures. The frozen
preregistration, configuration, schema, methods, thresholds, and prior
observations were not changed.

The following command verifies the completed artifacts without writing
outputs. It remains usable from a checkout containing the committed
bundle:

```bash
export PATH="$PWD/work/bootstrap/bin:$PATH"
uv run --locked --no-sync python scripts/run_v0_3_7_diagnostic_closure.py --verify
```

The first generation used `--check-only`, then `--execute`, before the
outputs existed. Those modes now reject the completed inventory. Use
`--verify` to inspect completion; preserve the first decision and manifest.
