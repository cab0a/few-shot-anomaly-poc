# v0.2 Memory-Bounded Fresh-Process Timing Runner

## 日本語概要

本書は、同じCPU・WSL環境でDINOv2の正式CPU timing workloadを実行するためのmemory-bounded runner実装記録です。固定合成入力をmemory-mapped storeへ生成し、referenceとqueryを一枚ずつ連続配列へcopyして、224と448を別processで順番に実行します。

25回のwarm-up、各解像度300回のtiming、median、nearest-rank p95、peak RSS、OOM、process終了、欠測、JSON/CSVを固定しました。現段階で実行したのはinput再生成、timing loop、fake worker、isolated PyTorch primitiveのテストだけで、正式DINOv2 timing結果はありません。詳細は以下の英語本文を参照してください。

## English Summary

This record implements the preregistered memory-bounded DINOv2 CPU timing runner without executing the formal model workload. It generates the exact PCG64 inputs into an ignored memory-mapped store, copies one decoded image at a time outside the timer, builds the 20-reference feature bank sequentially, runs `224` and `448` in distinct isolated processes, and preserves all observations, failures, process exits, peak RSS values, and JSON/CSV identities. Contract tests use deterministic callables and fake workers; they are not DINOv2 performance evidence.

## Fixed Synthetic Input Store

[`dinov2_timing.py`](../src/few_shot_anomaly_poc/dinov2_timing.py) creates one local NumPy `.npy` memory map outside Git. It uses `numpy.random.Generator(numpy.random.PCG64(42))` and generates 20 references followed by 100 queries. Every array is `512 x 512 x 3`, `uint8`, and sampled from integers in `[0, 256)`.

The implementation tests fix the following identities under NumPy `2.5.1`:

| Item | SHA-256 |
| --- | --- |
| Complete `.npy` store | `b57319a8aa9fc8c27d1daa22acf8640a31cf366074a2c42e14e65ff55f4501b7` |
| `synthetic/reference/000` | `023bb0389ea38626636c3b42cd8ea40ddd297d7a4103ba8343eb0af694bdbc15` |
| `synthetic/query/000` | `751b0ba5f549fafd2e6f77d9adb0f2d991845a4b273ef832790fd66a7ff16734` |
| `synthetic/query/099` | `7f68d98dc55025ddb09d5ce707428205e1bade9f0f50ddf49b08cfcbcc391310` |

The `.npy` file is `94,371,968` bytes including its header. The public manifest contains the logical store ID, shape, dtype, byte count, whole-file SHA-256, and 120 per-image identities. It never contains the local physical store path or raw input bytes.

The worker verifies the complete store hash, opens it read-only with `allow_pickle=False`, copies one selected image into a C-contiguous array, verifies that image's SHA-256, and only then enters preprocessing or timing.

## Bounded Resident-Memory Policy

Reference fitting preallocates only the final fixed-resolution feature bank. It then:

1. copies one reference image from the memory map;
2. extracts normalized patch features;
3. copies those features into the preallocated bank slice;
4. releases the extracted feature object and decoded source array; and
5. proceeds to the next reference.

Warm-up and timing copy one query before each scoring call. Input-store access, copying, and per-image hash verification occur outside the existing decoded-RGB-to-scalar timing boundary. Batch scoring and simultaneous decoded retention of all 120 source images are not implemented.

The worker records process peak RSS at process start, after model load, after memory-bank construction, after timing, or at a caught failure. Peak RSS remains diagnostic. A real memory exception, process termination, nonzero child exit, missing artifact, or incomplete observation set is a hard failure.

## Fixed Timing Loop

For each resolution, the worker:

1. constructs and strictly loads the fixed CPU model;
2. builds the separate 20-reference memory bank outside timing;
3. performs 25 untimed calls with `synthetic/query/000`;
4. executes query IDs `000` through `099` in ascending order for three passes;
5. records all 300 durations with `time.perf_counter_ns`;
6. records each scalar score, status, and failure identity;
7. calculates median from sorted observations 150 and 151; and
8. calculates p95 by nearest rank 285.

No invocation is retried, discarded, replaced, or treated as an outlier. A caught failure is recorded once, the resolution stops, and every unattempted invocation is counted as missing. A resolution passes only when all 300 invocations succeed with finite scores and p95 no greater than `1,000,000,000 ns`.

## Fresh-Process Orchestration

[`run_v0_2_cpu_timing.py`](../scripts/run_v0_2_cpu_timing.py) is the parent. It:

- requires a clean execution commit and an ignored `work/` output root;
- reruns the memory-bounded precondition checker for that same execution commit;
- creates the input store only after conditions 1–6 pass;
- starts resolution `224` first;
- waits for and preserves its result;
- starts resolution `448` second regardless of the first resolution's pass or fail result;
- derives both workers from the exact isolated CPU-only Python environment;
- sets the fixed thread, isolation, hash-seed, accelerator, and xFormers environment;
- captures child stdout and stderr only in ignored local logs;
- validates each worker JSON and observations-CSV hash; and
- writes one parent summary without storing commands, process IDs, or absolute paths.

The fake-worker integration test starts the two commands sequentially and verifies different process IDs. Those process IDs are test assertions only and do not enter a committed artifact.

## Resolution-Worker Boundary

[`run_v0_2_cpu_timing_resolution.py`](../scripts/run_v0_2_cpu_timing_resolution.py) runs under the isolated Python executable with `-I -B`. Each child independently verifies:

- the current-run precondition artifact and execution commit;
- the fixed import-smoke, acquisition, strict-load, source, and checkpoint identities;
- the exact CPU-only PyTorch build and installed distributions;
- the hash-addressed DINOv2 source extraction;
- disabled network operations and absent xFormers imports;
- four intra-op and one inter-op PyTorch threads;
- deterministic algorithms and float32 CPU model state; and
- the input manifest, store, resolution, and output non-overwrite boundary.

Model construction, reference fitting, and all query scoring happen inside that one child only. The parent never imports PyTorch or DINOv2.

The parent selects `448` when both resolutions pass, selects the only passing resolution when exactly one passes, and returns `DO_NOT_PROCEED` when neither passes. A timing-stage pass authorizes a separate first-10-score offline reproduction process; it does not yet return the final preflight `PROCEED` decision.

## Failure Preservation

The machine-readable boundary distinguishes:

- Python `MemoryError`;
- framework out-of-memory text in the causal exception chain;
- input-copy or hash failure;
- scoring or timing-clock failure;
- non-finite or out-of-range scores;
- warm-up failure;
- incomplete timed observations;
- missing or invalid child artifacts;
- disagreement between child exit code and artifact decision;
- operating-system or unhandled process failure; and
- attempted network or unexpected xFormers use.

Stored failure records contain stable categories, exception types, phases, counts, and exit codes. They do not copy arbitrary exception messages or machine-specific paths into public JSON.

## Verification Without Formal Timing

The root environment verifies input generation, fixed hashes, one-image copies, call order, counts, latency arithmetic, failure handling, CSV structure, resolution selection, and process isolation:

```bash
uv sync --locked
uv run --locked --no-sync ruff check .
uv run --locked --no-sync pytest
```

The separate PyTorch test verifies one-at-a-time reference fitting and exact bank shape in the isolated environment. It uses a fixed fake token model, not DINOv2 performance data.

## Preserved Boundary

This implementation milestone did not:

- execute the formal 25-plus-300 DINOv2 workload;
- calculate a real DINOv2 median or p95;
- observe DINOv2 peak RSS under the formal workload;
- select `224` or `448`;
- access VisA, `pcb2`, image content, or labels;
- calibrate a threshold;
- calculate anomaly metrics;
- adopt or reject DINOv2; or
- change the one-second latency gate in response to a result.
