## English Summary

The v0.2.4 stage fitted all three fixed methods from the 20 known-normal references and fixed one threshold per method from 881 separate known-normal calibration images. Every reference and calibration score completed successfully. Final-test assets, labels, the sealed mapping, metrics, formal latency, and decisions remained outside this stage.

## Status

**Complete. The three fitted-state identities and normal-only thresholds are fixed. The evaluation boundary remains unrevealed.**

The execution commit was `6548bfa97e7e834bd88b0efbbd1b557ae85e242c`. It was pushed to `origin/main`, and both CI and Quick Start completed successfully before execution.

## Authorized Scope

This stage was limited to:

- verifying every byte identity in the fixed 20-image normal-reference manifest and 881-image normal-calibration manifest;
- decoding those 901 known-normal images;
- fitting `ecc_residual`, `patch_hog_ocsvm`, and `dinov2_vits14_224_nn` from the 20 references;
- scoring only the 881 normal-calibration images;
- applying the fixed nearest-rank 95th-percentile threshold rule independently per method; and
- preserving public JSON/CSV evidence and external fitted-state hashes without overwriting an existing output.

The runner did not receive a final-test manifest, final-test source path, label, HMAC key, or sealed mapping. It did not calculate a final-test metric, formal CPU latency summary, failure case, gate result, or decision.

## Threshold Rule

For each method, the runner sorted the 881 records by `(anomaly_score, source_path)`, selected rank `ceil(0.95 × 881) = 837`, and classified only scores strictly greater than that threshold as anomalous. A scoring failure would always be classified as anomalous using the fixed finite failure score. No scoring failure occurred in this stage.

The resulting calibration count above threshold was 44 for every method. The gate remains defined on the untouched final-test normal subset; the calibration FPR cannot satisfy or waive that gate.

## Memory-Bounded Execution

The root environment verified and decoded one normal image at a time, converted BGR to RGB, resized directly to `512 × 512` with area interpolation, and wrote a temporary C-contiguous `uint8` memory map under ignored `work/`. The classical methods ran in the root locked environment. The DINOv2 worker ran in the separately locked CPU-only environment, read one stored image at a time, applied the fixed 224-pixel model preprocessing, and performed no network access.

The temporary 901-image RGB store was removed after completion. Binary fitted states remain outside Git under ignored local storage. Only their SHA-256 identities appear in the public fit records. The observed execution duration and memory use are diagnostics, not the preregistered per-image CPU latency evidence.

## Known Limitations

- Normal-only calibration does not measure anomaly separation or final-test transfer.
- One category, one fixed reference set, and one fixed normal-calibration partition are used.
- No confidence interval or reference-set sensitivity analysis is included.
- The DINOv2 dependency and model-asset boundary is materially more complex than either classical method.
- The post-freeze orchestration commit is preserved as an explicit process limitation rather than described as part of the earlier frozen source commit.
- No image-content review was performed, so this stage makes no visual failure-cause claim.
