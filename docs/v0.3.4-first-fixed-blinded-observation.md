## Operator and Reviewer Separation

The operator verifies metadata, controls execution, and retains the audit
records. The reviewer receives only one opaque ID, its decoded image pixels,
and a blank fixed form. The operator must not act as the reviewer if they
have already seen the selected-ID-to-method or error mapping.

Choose one human reviewer or one fresh agent with no inherited conversation
or repository context. Keep that same reviewer for all 28 images. A fresh
agent requires explicit user authorization. Do not send this operator
document, configuration, source files, parent results, linkage, scores,
labels, hashes, or semantic paths to the reviewer.

The file exchange enforces the presentation allowlist; it is not an OS
sandbox. A reviewer with filesystem tools must be instructed to read only
the assigned exchange directory and must obey that restriction. Record the
reviewer type with `--reviewer-kind human` or `--reviewer-kind isolated_agent`.
An agent observation must be described as such in the eventual report; it
does not constitute human reviewer validation or inter-rater evidence.

## Start the First Observation

Arrange the independent reviewer before starting. For a human reviewer:

```bash
uv run --locked --no-sync python scripts/run_v0_3_4_first_observation.py \
  --reviewer-kind human
```

For an explicitly authorized fresh agent, use `--reviewer-kind isolated_agent`
instead. Repeat any custom external-directory arguments from preflight.
Keep the operator process running while the reviewer works.

The session is exclusively created at
`work/v0.3.4/first-observation/`. It contains separate `operator/` and
`reviewer/` directories. The operator directory records the source commit,
reviewer type, each attempted ID before byte access, and every returned
response. It is not reviewer input.

The reviewer directory gains one opaque-ID subdirectory at a time, in
ascending ID order. Each contains only:

- `pixels.png`: a lossless transport of the original decoded BGR pixels,
  with no resizing, crop, overlay, annotation, or source metadata;
- `item.json`: exactly `asset_id`, `pixels`, and the blank `form`; and
- `item.ready`: an empty marker written after the image and form are durable.

The reviewer writes the ten form fields to `response.json`, then creates
an empty `response.ready` file last. The operator waits up to one hour per
image, validates the response, and only then presents the next image.
Transport PNGs remain ignored local files and must never be committed or
published. No anomaly scorer, comparison image, or method-case join is
part of this process.

## Reviewer-Only Instructions

Copy only the following instructions and the assigned reviewer-directory
path to the independent reviewer:

> Read only the assigned reviewer exchange directory. Do not read repository
> files, other conversations, or parent directories. Wait for an opaque-ID
> directory containing `item.ready`, and process the ready directories once
> each in ascending ID order. Read `item.json` and display `pixels.png` at
> original resolution without editing, resizing, cropping, or adding overlays.
> Use an original-detail image viewer when one is available.
>
> Complete exactly the ten fields in `form`. Set `review_status` to `reviewed`
> or `unreadable`. Each visibility field must be `yes`, `no`, or `uncertain`.
> Use `uncertain` when the visible pixels do not support a judgment. Describe
> only what is visible; keep any inferred cause separate. Do not invent a
> comparison baseline or infer whether an image should pass inspection.
>
> `visible_observation` must contain 1 to 300 characters with no line breaks.
> `inferred_cause` must be null or a separately labeled hypothesis of 1 to 300
> characters with no line breaks. Do not add fields or include the opaque ID
> inside the response object. Write the completed form as UTF-8 JSON to
> `response.json`, then create an empty `response.ready` file. Never revise a
> submitted response, revisit a submitted image, or open another image source.
> Stop after 28 responses. If you encounter unrelated metadata or cannot
> continue, tell the operator and stop without fabricating observations.
