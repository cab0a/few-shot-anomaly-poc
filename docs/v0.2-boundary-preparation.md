## English Summary

The first fixed v0.2 boundary run verified the preregistered VisA archive and official split, created 20 normal references and 881 normal calibration inputs, and staged all 200 final-test inputs behind opaque IDs. Protected paths, labels, the HMAC key, raw bytes, and normal manifests remain outside Git. No image was decoded, fitted, calibrated, scored, displayed, or evaluated.

The runner required that commit to equal both local `HEAD` and `origin/main`, required a clean worktree, and required the preregistration and machine-readable contract commits to be ancestors before reading the fixed inputs.

## Normal-Only Partitions


Records were sorted by digest and then relative path. Ranks 1–20 became `reference`; every remaining normal training record became `calibration`.

## Opaque Final-Test Boundary

The runner read final-test labels only while constructing the protected reveal-side mapping. It then:

1. generated one 32-byte key with the operating system cryptographic random source;
2. ordered final-test source paths by HMAC-SHA-256 and path tie-break;
3. assigned sequential IDs from `asset-000000` through `asset-000199`;
4. copied encoded image bytes to ignored `assets/<opaque-id>.<extension>` paths;
5. verified every staged byte count and SHA-256 against its source;
6. wrote the scorer manifest with exactly `asset_id`, `relative_path`, `byte_count`, and `sha256`; and
7. wrote the source path and class only to the separate protected mapping.

## Reproduction and Non-Overwrite Rule

The fixed command was:

```bash
uv run --locked --no-sync python scripts/prepare_v0_2_boundary.py \
  --execution-commit 0fd5ec2d9d477fe9298f6b5468cec35a1111314f
```

The command requires the exact external archive and split and refuses to overwrite either the external boundary root or the public artifact root. It cannot be run a second time against the completed location.

The random HMAC key intentionally makes a newly created boundary a different boundary. Reproduction of later fitting, scoring, and evaluation therefore uses this preserved key, opaque asset set, normal manifests, and their fixed identities; it does not regenerate a new ordering after results exist.
