## Decision Audit

The fixed hard-gate order was applied without a weighted aggregate or waiver.

- ECC residual: first failure at anomaly recall, `0.13 < 0.90`.
- Patch HOG + One-Class SVM: first failure at anomaly recall, `0.16 < 0.90`.
- DINOv2 224 NN: first failure at normal FPR, `0.07 > 0.05`.
- Project: all methods are `REJECT`, so no method is selected and the project is `REJECT`.

Later gates are explicitly `not_evaluated` after the first failure. Measured p95 latency, fixed reference count, no-anomaly-label evidence, and offline reproduction remain preserved as evidence but do not override the ordered stop rule.

No failure image was reviewed. Because no method was otherwise gate-passing, the preregistered qualitative review was not needed to determine a decision. The schema-required `no_material_boundary` value is a neutral placeholder for these early rejections and is not a visual-review finding.

## Reproducibility Review

### Clone-Only Verification

The normal project environment can verify code, contracts, frozen identities, metrics, decisions, and the complete manifest without downloading VisA or model assets:

```bash
uv sync --locked
uv run --locked --no-sync python scripts/verify_environment.py
uv run --locked --no-sync ruff check .
uv run --locked --no-sync pytest
```

The test suite checks:

- deterministic ECC, Patch HOG, threshold, classification, metric, latency, and decision primitives;
- the fixed DINOv2 scoring and timing contracts without requiring PyTorch in the root environment;
- exact config, schema, preregistration, boundary, fit, calibration, score, reproduction, reveal, metric, failure, and decision identities;
- all hard-gate names and order, the first failed gate, and downstream stop behavior;
- all 35 manifest entries, record counts, and file hashes; and
- absence of raw or derived image files from the final evaluation bundle.

Two torch-backed integration modules are expected to skip in the root environment because DINOv2 execution remains isolated in its separate pinned environment. Their non-torch contracts and the committed DINOv2 artifacts remain verified by the root suite.

## Handoff

v0.2 is a completed negative CPU-only few-shot anomaly PoC. Its value is the auditable progression from requirements and research through immutable scoring, evaluation, failure selection, and rejection—not a claim of acceptable inspection performance.

The next technical step is a separately preregistered development-only diagnostic of the mechanically selected error cases and normal-score transfer. Only evidence from that diagnostic could justify one bounded method change and a new untouched validation.
