## English Summary

This report presents the fixed VisA `pcb1` evaluation, the `REJECT` decision for both methods, operating-point failures, ranking metrics, selected errors, interpretation, limitations, and proposed next validation. It preserves the negative result without revising preregistered gates.

## Executive decision

**Project decision: `REJECT`.**

Neither shortlisted method satisfied the preregistered operating-point gates
on the fixed VisA `pcb1` final test. ECC-aligned normal-template residual
failed the normal false-positive-rate, anomaly-recall, and CPU p95 latency
gates. Patch HOG + One-Class SVM failed the normal false-positive-rate and
anomaly-recall gates.

This is a useful negative PoC result. The two CPU-only, normal-only baselines
do not justify adoption under the hypothetical v0.1 requirements. Their
ranking metrics do not override the failed hard gates.

## Question evaluated

This public case study asks whether either of two deliberately small methods
can justify a follow-up visual-inspection prototype when:

- only 20 normal reference images may be used for fitting
- anomaly training labels are unavailable
- scoring must run on CPU
- the operating threshold must be calibrated from normal images only
- the final decision must be reproducible from fixed assets and settings

The stakeholder and requirements are hypothetical. This report is not a
customer result, a production-readiness claim, or evidence about an untested
inspection process.

## Preregistered decision protocol

The requirements, method definitions, threshold rule, metrics, latency
boundary, failure-case rule, and hard-gate order were frozen before final-test
scoring. A method could pass only if every gate passed:

| Order | Hard gate | Pass condition |
| ---: | --- | --- |
| 1 | Final-test normal FPR | `<= 0.05` |
| 2 | Final-test anomaly recall | `>= 0.90` |
| 3 | CPU p95 scoring latency | `<= 1.0 s/image` |
| 4 | Normal reference count | `<= 20` |
| 5 | Anomaly training labels | none used |
| 6 | Reproducibility | verified |

No weighted aggregate score, result-driven gate revision, or hard-gate waiver
was allowed. AUROC and AUPRC were descriptive ranking metrics, not acceptance
gates.

The frozen protocol is recorded in the
[evaluation plan](evaluation-plan.md), the
[method specification](method-specification.md), and the
[pre-evaluation freeze record](pre-evaluation-freeze.md).

## Data and partitions

v0.1 uses only the official VisA `pcb1` one-class split:

| Partition | Use | Count | Labels available to the method |
| --- | --- | ---: | --- |
| Normal reference | fit normal representations | 20 | normal status only |
| Normal calibration | fix one threshold per method | 884 | normal status only |
| Final test | one fixed scoring and decision run | 200: 100 normal, 100 anomaly | joined only at evaluation |

Seed `42` and a version-independent SHA-256 path-ranking rule fixed the 20
reference IDs. Reference, calibration, and final-test path sets were checked
for overlap. Raw VisA images, masks, and the official split file remain outside
Git.

VisA is separately licensed under CC BY 4.0. Dataset provenance and attribution
are recorded in the [acquisition record](data-acquisition-record.md). No VisA
image is reproduced in this report.

## Compared methods

### ECC-aligned normal-template residual

Twenty normal references build one aligned normal template. Each input is
registered to that template with bounded ECC alignment, and a robust aggregate
of the valid residual image becomes the anomaly score.

### Patch HOG + One-Class SVM

Each image is divided into fixed-position patches. HOG features are scaled and
modeled with one One-Class SVM per patch position using reference-derived
features only. The most anomalous patch scores are aggregated into the image
score.

The implementation did not include DINOv2, PatchCore, AnomalyDINO, an
autoencoder, or pixel-level evaluation.

## Fixed calibration

Both methods scored all 884 normal calibration images without a scoring
failure. The nearest-rank 95th-percentile rule produced:

| Method | Fixed threshold | Calibration images above threshold | Realized calibration FPR |
| --- | ---: | ---: | ---: |
| ECC residual | `0.688464437424507` | 44 / 884 | `0.049773755656108594` |
| Patch HOG + One-Class SVM | `0.17611826509314352` | 44 / 884 | `0.049773755656108594` |

These thresholds remained unchanged during final evaluation.

## Interpretation

The AUROC and AUPRC values show that both scores contain some ranking signal.
They do not show that either fixed operating point is usable. At the
normal-only thresholds, ECC detected 21 of 100 anomalies and Patch HOG detected
19 of 100. The resulting recall gaps are too large to justify adoption under
the hypothetical 90% requirement.

The normal-only calibration FPR was approximately 4.98% for both methods, but
the final-test normal FPR increased to 9% and 10%. This is evidence that the
fixed normal operating point did not transfer to the final-test normal subset
within the required tolerance. It is not evidence of a specific cause.

Patch HOG passed the stated CPU p95 gate on the recorded machine. ECC did not.
The latency result covers decoded grayscale input through image score and
excludes file I/O and one-time reference fitting. It was measured on an
Intel Core i7-3630QM CPU under WSL2 using one warm-up pass and three timed
passes over 200 images. Each method contributed 600 timed observations.

## Failure-case evidence

For each method, the evaluation mechanically selected:

- the five highest-scoring false positives
- the five lowest-scoring false negatives

Selection used only fixed scores, predictions, labels, and deterministic
path tie-breaks. Image content was not opened or displayed. Therefore this
report does not claim that alignment, illumination, board layout, defect size,
or another visual factor caused a selected error.

The selected records, scores, margins, and ranks are preserved in each
method's `failure-cases.csv` under the
[final evaluation bundle](../artifacts/v0.1/evaluation/visa-pcb1-v0-1-final/).
The absence of an image-content review is retained as
`guardrail_required`, but that disposition cannot waive a failed hard gate.

## Known limitations

- Only one dataset category, one official split, one fixed seed, and one
  20-image reference set were evaluated.
- The public benchmark does not represent an identified production camera,
  process distribution, defect taxonomy, or cost model.
- No confidence interval, repeated-reference-set analysis, or statistical
  significance claim is provided.
- The programmatic scorer received no class field and did not branch on class.
  However, the upstream VisA relative paths contain class-semantic directory
  names. The control is therefore a programmatic label-use boundary, not a
  double-blind human study. Opaque asset IDs should be used in a future
  protocol.
- CPU latency is specific to the recorded hardware, software environment, and
  scoring boundary.
- Failure cases were selected but their image content was not reviewed, so no
  causal failure taxonomy is claimed.
- Image-level metrics do not measure anomaly localization.
- Synthetic integration results elsewhere in the repository are plumbing
  checks and are not VisA performance evidence.
- These results must not be generalized to other VisA categories or real-world
  inspection data.

## Recommended next validation

The v0.1 decision remains `REJECT`. The following are proposals for a new,
separately preregistered study; they do not revise this final test:

1. Review the already selected failure images under the documented CC BY 4.0
   boundary and record visible observations without causal overclaiming.
2. Use a new development-only normal partition to test whether score drift,
   registration diagnostics, or fixed spatial aggregation explain the weak
   operating-point transfer. Do not tune against the completed v0.1 final test.
3. Replace class-semantic paths with opaque asset IDs before scoring and human
   review.
4. If a stronger representation is justified, preregister a v0.2 DINOv2 patch
   nearest-neighbor comparison with pinned weights, dependency licenses,
   CPU budget, and a new untouched evaluation boundary.
5. Keep pixel-level evaluation out of scope until image-level viability and
   the intended localization requirement are defined.
