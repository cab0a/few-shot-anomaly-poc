## English Summary

The v0.2.6 stage regenerated the first ten committed opaque scores for each frozen method in a separate fresh offline process. All 30 comparisons matched score status and failure code and had an absolute score difference of `0.0`, within the preregistered `1e-6` tolerance. A pre-reveal checkpoint then bound all 23 prior public evaluation files to a pushed evidence commit and one deterministic bundle identity without accessing labels or protected mapping inputs.

## Status

**Complete. The fixed first-ten reproduction and pre-reveal checkpoint are committed and pushed. The label boundary remains closed.**

This is reproducibility evidence for already committed label-free scores. It is not anomaly-performance evidence, a comparison of accuracy, or an adoption decision.

## Fixed Execution Sequence

The implementation commit `2ce72b40e5ef69b89e7b4f092f6f82f99e4e4fd9` was pushed and passed the repository CI and Quick Start workflows before execution. The runner then:

1. required a clean worktree whose `HEAD` exactly matched `origin/main`;
2. verified the fixed configuration, artifact schema, opaque scoring manifest, fitted-state hashes, and all committed v0.2.5 score-side hashes;
3. selected only `asset-000000` through `asset-000009` in their fixed order;
4. started one new `python -I -B` process per method with network operations blocked;
5. regenerated one score per selected opaque asset without timing or retry;
6. compared score, status, and failure code against the committed canonical record;
7. wrote one non-overwriting reproduction CSV per method; and
8. preserved a failed comparison as `fail` rather than changing the tolerance or running it again.

The ECC residual and Patch HOG + One-Class SVM workers used the fixed project environment and their hash-verified pickled state. The DINOv2 worker used the isolated locked CPU environment, fixed source and checkpoint assets, hash-verified tensor state, and a temporary ignored first-ten RGB input store. The temporary stores and worker reports were not committed.

The runner did not repeat the 200-image final-test scoring workload. It regenerated only the preregistered first ten scores for each method.

## Pre-Reveal Checkpoint

After the reproduction artifacts were committed, pushed, and passed CI, the checkpoint generator used evidence commit `30e830e3f805f2410c669c0b8c2da6cb27894ca5`. It verified that every expected public file existed at that commit with the same bytes and that no extra evaluation artifact was present.

The bound inventory contains 23 files:

- two shared records: boundary and pre-evaluation freeze;
- three fit, three calibration-score, and three calibration-summary artifacts;
- three final-test score, three classification, and three latency-observation artifacts; and
- three offline-reproduction artifacts.

The deterministic bundle identity sorts repository-relative artifact paths and hashes each UTF-8 path, a null separator, the file SHA-256 in lowercase ASCII, and a newline. The resulting `label_free_bundle_sha256` is `b3fb2a1283117350cf3c016ae284d3558aa7ff9ea1cf1c6beb65eba54c5cb389`.

[`pre-reveal-checkpoint.json`](../artifacts/v0.2/evaluation/visa-pcb2-v0-2-final/pre-reveal-checkpoint.json) has SHA-256 `4bf7d63da308868933a8967a6922fc439f95a524bf54cd8a38ff39f894219b07`. It records:

- scoring source commit `ba23a2fe12a715161b420bc7d73d42f4de3bfc8c`;
- pushed label-free evidence commit `30e830e3f805f2410c669c0b8c2da6cb27894ca5`;
- all three fixed methods in preregistered order;
- 200 score records per method;
- reproduction status `pass` for every method;
- `git_push_verified: true`; and
- `labels_accessed: false`.

The checkpoint does not hash itself. It binds the complete preceding label-free evidence set.

## Boundary Evidence

Throughout this stage:

- `final_test_label_revealed` remained `false`;
- no semantic source path was provided to a scoring worker;
- the official split, HMAC key, and sealed mapping were not provided to a scoring worker;
- no image was displayed or manually selected;
- network operations were blocked in every reproduction worker; and
- no metric, failure case, hard-gate trace, or decision was calculated.

The public CSV and JSON artifacts contain no raw VisA image or model-state bytes. Raw data, fitted state, model assets, temporary arrays, and boundary secrets remain outside Git.

## Verification

Clone-only verification checks the committed hashes, schemas, exact first-ten rows, tolerance results, protected-field exclusion, bundle identity, checkpoint fields, and commit ancestry:

```bash
uv run --locked --no-sync pytest -q \
  tests/test_committed_v0_2_offline_reproduction_run.py \
  tests/test_committed_v0_2_pre_reveal_checkpoint.py
```

The formal reproduction runner refuses overwrite and the preregistration forbids a rerun after a failed check. It is therefore not a routine reproduction command. Re-executing it also requires the separately licensed VisA assets, external fitted states, fixed DINOv2 assets, exact isolated environment, and the recorded clean pushed source commit.

## Known Limitations

- The check covers only the fixed first ten opaque assets, not a second 200-image scoring run.
- Exact equality was observed on one machine and the same fixed software environments; portability to another CPU or dependency set is not established.
- Reproducibility does not establish correct anomaly ranking, acceptable false-positive rate, acceptable recall, or useful failure modes.
- The final-test class distribution and all class-dependent results remain unknown at this checkpoint.
- No visual inspection or causal failure analysis has been performed.

## Next Authorized Stage

The next milestone is **v0.2.7 — Label Reveal, Metrics, and Failure Cases**. It may join the sealed labels to the immutable score-side records only by the exact ordered opaque asset IDs. Missing, extra, duplicate, or out-of-order IDs must stop the evaluation. It may then calculate the fixed image-level metrics and mechanically select false positives and false negatives. It must not change a score, threshold, tolerance, metric, hard gate, or method.

Hard-gate decisions remain deferred to v0.2.8.
