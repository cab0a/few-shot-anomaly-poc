## English Summary

This milestone implements a positive-allowlist first-pass review primitive and verifies it with 28 generated temporary images. The reviewer callback receives only an opaque asset ID, immutable pixels at the decoded extent, and the blank fixed form. Synthetic checks cover exact inventory order, one nominal decode per asset, metadata exclusion, byte verification, schema enforcement, deterministic CSV round trips, completion checkpoint construction, and rejection behavior. No VisA image or anomaly scorer entered the run.

## Status

## Positive Reviewer Allowlist

The dedicated reviewer view model has exactly three fields:

- `asset_id`;
- `pixels`; and
- `form`.

The form has exactly the ten preregistered reviewer-entry fields. Contract identity and diagnostic identity are added by the collector after the response; the reviewer does not enter or receive them. Internal byte count and SHA-256 are used for verification but are not members of the view model.

Method, case type, true class, prediction, score, threshold, margin, rank, source or semantic path, filename, and another method's selection state are not inputs to the callback. The primitive has no API for the separately committed `review-case-linkage.csv`, failure cases, revealed labels, score artifacts, or sealed mapping.

This is a positive allowlist: an alias for a protected concept is not authorized merely because that alias is absent from a negative list.

## Byte and Decode Boundary

The future real loader is restricted to one computed opaque filename for an already validated selected ID. Before decode, it requires:

- membership in the fixed 28-ID set;
- a regular, non-symlink file under the supplied opaque asset root;
- exact recorded byte count; and
- exact recorded SHA-256.

It then performs one unchanged-color OpenCV decode, requires a nonempty C-contiguous BGR `uint8` array, and copies the decoded bytes behind an immutable buffer. No resize, crop, overlay, transform, annotation, or score operation occurs. Hash mismatch and symlink tests confirm rejection before a reviewer callback can receive pixels.

In v0.3.3 this loader was used only against generated temporary PNG-encoded fixtures stored under opaque `.jpg` names. The loader did not resolve or touch a VisA image.

## Observation Enforcement

The collector requires the exact 28 IDs in ascending order, with no missing, extra, duplicate, or reordered record. Each nominal synthetic asset was loaded and reviewed once. Reviewer responses use exact-key validation:

- `review_status` is one of the two fixed values;
- every visibility field is `yes`, `no`, or `uncertain`;
- `visible_observation` contains 1 to 300 Python Unicode code points;
- `inferred_cause` is null or contains 1 to 300 code points; and
- control characters, unknown fields, and protected-field injection are rejected.

The serializer uses fixed column order, UTF-8, LF endings, and exclusive creation. Two synthetic serializations and writes produced identical bytes. A read-back validation reproduced all 28 in-memory records, and a second write to the same path was rejected.

The completion checkpoint fixes the inventory hash, observation hash, counts `28/28/28`, ascending order, `first_pass_complete=true`, `protected_metadata_exposed=false`, and `method_metadata_joined=false`. A later method-case join must not proceed without that checkpoint.

## Synthetic Verification Result

All 18 fixed checks passed:

- exact 28-item processing, order, and one nominal callback per asset;
- exact safe view and blank form fields;
- original decoded extent and values preserved;
- pixels backed by immutable memory;
- deterministic CSV bytes and exact round trip;
- closed completion checkpoint;
- protected sentinel absent from callback-visible text, CSV, and report;
- protected-field injection rejected;
- missing, duplicate, and reordered inventories rejected;
- hash mismatch, symlink, and unselected asset rejected; and
- output overwrite rejected.

The committed report records `synthetic_image_decoded=true`. It separately records all of the following as `false`: `visa_image_accessed`, `v0_3_selected_image_accessed`, `image_displayed`, `anomaly_scorer_executed`, `diagnostic_score_computed`, `real_observation_written`, `real_diagnostic_artifacts_modified`, and `raw_or_derived_image_committed`.

## Claim Boundary

v0.3.3 demonstrates that the interface and serializer enforce the intended metadata boundary under controlled synthetic fixtures. It does not demonstrate:

- that image content cannot reveal an apparent defect;
- information-theoretic secrecy of the public selected IDs;
- human reviewer consistency or inter-rater reliability;
- correct visual interpretation of VisA assets;
- a relationship between a visible property and a method score; or
- support for any framing, exposure, or blur hypothesis.
