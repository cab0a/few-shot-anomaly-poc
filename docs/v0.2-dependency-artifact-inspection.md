## Fixed Acquisition Boundary

The acquisition used the exact URLs, filenames, versions, and SHA-256 values in [`uv.lock`](../environments/v0.2-preflight/uv.lock). The accepted artifact hosts were limited to:

- `files.pythonhosted.org`; and
- `download-r2.pytorch.org`.

Each transfer:

1. wrote to a uniquely named `.part` file under the ignored `data/external/` boundary;
2. calculated SHA-256 while streaming;
3. required an allowlisted effective HTTPS host;
4. required the locked SHA-256 before atomic rename;
5. required the locked size when present;
6. required the separately verified 191,815,667-byte size for the PyTorch wheel; and
7. refused to overwrite or merge with another artifact set.

The 17 accepted wheels remain under `data/external/`, which is ignored by Git. No wheel, extracted package tree, shared object, model file, or third-party license text was committed.

## Non-Executing Inspection Method

The inspection used Python standard-library ZIP and metadata readers. It did not call package installers, import package modules, invoke entry points, load shared objects, or extract wheel members.

For every wheel, it required:

- exactly one top-level `.dist-info/METADATA`;
- exactly one corresponding top-level `.dist-info/RECORD`;
- METADATA name and version equal to the locked distribution;
- no absolute path, traversal segment, backslash path, NUL, drive-like root, or case-folding collision;
- no symlink, special file, encrypted member, unsupported compression, duplicate target, or configured size-limit violation;
- every non-directory member represented exactly once in the top-level `RECORD`;
- SHA-256 and size verification for every non-`RECORD` member;
- the `RECORD` self-entry left unhashed as required by the wheel format;
- every metadata-declared `License-File` present;
- at least one reviewable license, notice, or attribution file; and
- SHA-256 and size records for every detected license material and native shared object.

Setuptools contains nested metadata for vendored packages. The inspector selects only the wheel's top-level dist-info root as controlling package metadata while still inventorying nested vendor licenses and notices.

## Internal License Observations

### NumPy

The wheel's principal `LICENSE.txt` maps bundled native files to their separate terms:

- `numpy.libs/libgfortran*.so`: `GPL-3.0-or-later WITH GCC-exception-3.1`;
- `numpy.libs/libquadmath*.so`: `LGPL-2.1-or-later`;
- the bundled OpenBLAS and LAPACK content: their included BSD-style terms; and
- other bundled source components: the separately included 0BSD, MIT, BSD, Zlib, and related notices.

These bundled runtime terms are more detailed than the top-level metadata expression. The exact license file and all 22 native-file identities are preserved in the inspection record.

### Setuptools

The wheel's top-level expression is MIT, while the inspected vendor material also includes:

- vendored `autocommand` license text under LGPL version 3;
- generated and copied `validate-pyproject` material under MPL-2.0;
- copied `fastjsonschema` material under BSD-3-Clause; and
- the individual permissive licenses for the other vendored packages.

The two setuptools `NOTICE` files and all discovered vendored license files are hashed in the record. The repository does not copy, modify, or redistribute those vendored files.

### PyTorch

The PyTorch METADATA declares 98 `License-File` entries, and all 98 matched wheel members. The inventory includes Apache-2.0 with LLVM exception, BSD, BSL-1.0, MIT, and the other terms represented by the published composite expression.

One archived third-party license path contains GPL-3.0 text for an upstream `cpr/test` subtree. No corresponding `cpr/test` source or binary member exists outside `.dist-info/licenses` in this CPU wheel. The text remains recorded rather than being omitted from the inventory.

The 12 runtime native paths include the Python extension, CPU libraries, OpenMP-compatible runtime, and test-named shared libraries shipped by the official wheel. Each path, size, and SHA-256 is recorded. This inspection does not claim a complete static or dynamic linkage analysis.

## Decision

### Result: `INSTALL`

The exact wheel set may be installed in the isolated local v0.2 environment because:

1. every whole-wheel digest matches its upstream-published SHA-256;
2. every archive and internal `RECORD` passed structural and content checks;
3. every distribution has reviewable internal license material;
4. additional bundled and vendored terms are recorded rather than hidden behind top-level metadata;
5. the use boundary is local, non-redistributed, and separate from the repository's PolyForm-covered work; and
6. no dependency artifact is committed.

This decision is conditional. It becomes `DO_NOT INSTALL` if the next step cannot use the exact wheel set offline, writes dependencies into Git, modifies a wheel, requires a source build, introduces another artifact, or cannot keep third-party terms separate.

## Reproduction

The inspection record is deterministic for the same lock and wheel bytes. The following downloads to a fresh temporary directory and writes a comparison record outside the repository:

```bash
review_root="$(mktemp -d)"
uv run --locked --no-sync python scripts/acquire_v0_2_dependency_artifacts.py \
  --artifact-dir "${review_root}/wheels" \
  --output "${review_root}/wheel-inspection.json" \
  --project-root . \
  --installation-decision INSTALL \
  --decision-reason "All locked wheels passed checksum, safe-archive, metadata, RECORD, and internal license-material inspection. Installation is limited to the isolated local v0.2 environment; vendoring or redistributing wheels requires a separate compliance review."
cmp \
  artifacts/v0.2/dependencies/wheel-inspection.json \
  "${review_root}/wheel-inspection.json"
```

This command downloads approximately 232 MB. It does not install, extract, import, or execute a downloaded package.
