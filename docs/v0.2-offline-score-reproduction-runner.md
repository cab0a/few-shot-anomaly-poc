## English Summary

This record implements the preregistered offline score-reproduction runner for the only latency-passing resolution, `224`. A parent starts one fresh isolated worker, which regenerates the fixed synthetic input store, reconstructs the same local DINOv2 model and 20-reference memory bank, and compares query IDs `000` through `009` with the first timing-pass scores in the committed artifact. The fixed absolute tolerance is `1e-6`. Contract tests have run, but the formal reproduction worker has not; no reproduction result or final preflight decision exists yet.

## Process Boundary

[`run_v0_2_offline_reproduction.py`](../scripts/run_v0_2_offline_reproduction.py) is the parent. Before creating output it requires:

- a full execution commit matching clean Git `HEAD`;
- a new output root inside the repository's ignored workspace;
- the exact isolated Python environment;
- the hash-addressed local DINOv2 source extraction;
- the fixed timing, acquisition, dependency, source, and input identities; and
- no overwrite of an earlier attempt.

The parent starts [`run_v0_2_offline_reproduction_worker.py`](../scripts/run_v0_2_offline_reproduction_worker.py) with the isolated environment's Python, `-I`, `-B`, no `PYTHONPATH`, no `PYTHONHOME`, disabled user site, `PYTHONHASHSEED=42`, CPU-only accelerator visibility, the fixed thread environment, and xFormers disabled.

The parent captures stdout and stderr into ignored local logs. It validates the worker artifact, worker exit code, execution commit, schema, and fixed resolution before writing its summary. A missing or malformed worker artifact and any exit/artifact disagreement become a structured failed parent result.

## Worker Sequence

The worker performs the following operations once:

1. revalidates clean Git execution identity and every fixed timing baseline hash;
2. regenerates 20 reference and 100 query arrays using PCG64 seed `42`;
3. verifies the complete regenerated manifest and raw-store SHA-256 against the timing input;
4. loads the exact local source, checkpoint, and CPU-only isolated environment under the network guard;
5. constructs the non-register `dinov2_vits14` model with the fixed deterministic settings;
6. rebuilds the 20-reference patch memory bank one image at a time;
7. scores query IDs `000` through `009` once, in ascending order and without timing;
8. compares each finite scalar with its first-pass timing score; and
9. writes the complete result without replacing an existing artifact.

There is no warm-up because this condition compares deterministic scalar values rather than latency. The reproduction worker does not add observations to the earlier latency sample.

## Comparison and Failure Rule

For each query, the artifact records:

- query index and asset ID;
- expected timing score;
- reproduced score;
- absolute difference; and
- whether the difference is no greater than `1e-6`.

The condition passes only when all 10 identities and scores are present in order, every score is finite, every fixed identity matches, no network operation is attempted, and the maximum absolute difference is no greater than `1e-6`.

The runner does not retry, replace, discard, or average a score. A numerical mismatch is retained as a complete failed comparison. A scoring exception, memory failure, non-finite score, blocked network attempt, missing observation, process failure, or identity mismatch produces `DO_NOT_PROCEED`. A favorable score cannot override an identity or boundary failure.
